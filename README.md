# Just Beachy Pools — pixel-perfect static replica

Production target: `justbeachypools.com`.
Output: ~332 static HTML files generated by a vanilla-Node build script.
Zero npm dependencies — only `fs` and `path` from the Node standard library.

## Folder structure

```
/
├── src/
│   ├── templates/    # one .html file per "page kind"
│   ├── partials/     # {{> partial-name}} fragments shared by templates
│   ├── content/      # site.json, hubs.json, services.json, cities.json,
│   │                 # city-services.csv, posts.json, faqs.json
│   ├── css/          # tokens.css, globals.css, components.css, <page>.css
│   ├── js/           # nav.js, carousel.js, forms.js, faq.js
│   └── assets/       # images / icons / fonts (copied verbatim into dist/)
├── build.js          # the build script (no deps)
├── package.json
├── .gitignore
└── dist/             # generated — gitignored
```

The repo root also still contains the 6 hand-built standalone pages
(`index.html`, `about-us.html`, …). They are the source-of-truth for visual
parity during the migration; the build pipeline reads `src/templates/*`
(which were extracted from those originals).

## Build

```bash
# Local development build — flat .html output, links rewritten to <slug>.html
npm run build

# Production build — nested <slug>/index.html, links keep trailing slashes
npm run build:prod

# Serve dist/ at http://localhost:3000
npm run serve

# Wipe dist/
npm run clean
```

The build is **idempotent** — running it 10 times in a row produces identical
output bytes.

### URL_MODE

- `URL_MODE=local` (default) — output files are flat (e.g.
  `dist/about-us.html`) and absolute hrefs are rewritten to point at `.html`
  files. Use this when you want to open `dist/index.html` directly in a
  browser.
- `URL_MODE=prod` — output files are nested (e.g.
  `dist/about-us/index.html`) and absolute hrefs keep their trailing
  slashes. Use this when deploying to a webserver that handles
  directory-index resolution (Nginx, Apache, Netlify, Cloudflare Pages,
  etc.).

## Adding a new page

1. **Content sheet row.** Add a row to the relevant content file in
   `src/content/` (e.g. `services.json` for an individual service,
   `city-services.csv` for a city × service combination, `posts.json` for a
   blog post, `hubs.json` for a hub).
2. **Template (only if the page kind is new).** Drop a new HTML file into
   `src/templates/` and add it to the route map (`SINGLE_ROUTES` for one-off
   pages or the iteration loop in `build.js` for collection pages).
3. **Page CSS (optional).** If the page needs unique styles, add
   `src/css/<slug>.css` and reference it from the template's `<head>`.
4. **Build.** `npm run build` to regenerate `dist/`.

## Placeholder syntax

- `{{> partial-name}}` — inline the contents of
  `src/partials/partial-name.html`.
- `{{key.path}}` — substitute a value looked up from the merged render
  context. The context is `{ site, nav, footer, cities, hubs, services,
  posts, faqs, cityServices, page }`. Use dot-paths to descend into nested
  objects (e.g. `{{site.address.full}}`).

Unresolved placeholders cause the build to fail loudly — there is no silent
fallback.

## Scripts (housekeeping)

- `scripts/migrate-pages.js` — one-shot transform that produced the initial
  set of templates in `src/templates/` by rewriting the standalone repo-root
  pages. Re-running it overwrites those templates; intended for the initial
  bootstrap and not part of `npm run build`.
